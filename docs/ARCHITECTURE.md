# Архитектура и сопровождение

## Поток работы

1. `configure.py` создаёт настройки конкретного ПК и адрес API для сборки Vite.
2. `server.py` инициализирует SQLite и при пустой базе запускает индексирование. Слушает только `127.0.0.1`.
3. `library.scan()` сначала собирает полный список файлов, затем одной транзакцией обновляет индекс. Ошибка чтения архива не превращается в массовое удаление записей. Пропавшие файлы получают `available=0`; их личные данные сохраняются на случай возвращения.
4. Браузер загружает интерфейс из IIS и получает с API каталог и сессионный токен. Страница содержит по 40 песен; список исполнителей ограничен 250 результатами, дальнейший поиск выполняется строкой поиска исполнителя.
5. `ratings.py` независимо обновляет метаданные исполнителей. SQLite — основное хранилище; JSON-снимки источника вспомогательные.
6. Открытие принимает ID каталога, повторно разрешает путь в архиве, проверяет расширение и Windows-ассоциацию и вызывает `os.startfile(..., 'open')`. Существующий экземпляр Guitar Pro получает файл через зарегистрированный механизм Windows/DDE.

## Хранилище и стабильность ID

`tabs.id` строится из SHA-1 относительного пути, укороченного до 20 hex-символов. Он нужен как идентификатор записи, не как контрольная сумма содержимого. Версии песен хранятся раздельно. Личные поля обновляются отдельно от файловых метаданных. Смена размера или mtime сбрасывает прежнюю оценку и ссылку источника. Изменение содержимого с сохранением обоих атрибутов не обнаруживается.

Записи исполнителей используют ID `bucket/slug`. Начальные имена выводятся из slug; подтверждённые отображаемые имена хранятся отдельно в `display_name` и `display_title` вместе с методом и источником. Поиск объединяет исходные токены и `name_search`, не меняя относительные пути и ID. SQL-значения параметризованы, порядок сортировки выбирается из разрешённого словаря. Запись сериализована через `RLock`, полное сканирование защищено отдельным lock. HTTP обслуживается потоками, а не асинхронным сервером.

## Границы доступа

- IIS видит только `dist/`; исходники, SQLite и архив не раздаются веб-сервером.
- API проверяет разрешённый Host и Origin. Изменения требуют токен текущего процесса из bootstrap; после рестарта клиент обновляет его.
- Это защита локального веб-интерфейса от посторонних веб-страниц, а не пользовательская авторизация или изоляция от других программ на том же ПК.
- Запрос открытия не принимает произвольную команду или путь. Ссылки и junctions исключены при обходе, разрешённый путь повторно проверяется перед открытием. Между проверкой и запуском остаётся обычный для локального файлового API промежуток; недоверенный локальный пользователь с правом менять архив вне модели применения.
- Импорт оценок разрешает HTTPS только на `www.gtp-tabs.ru/n/tabs/`, проверяет перенаправления до следующего запроса, ограничивает размер страницы, количество повторов и частоту начала запросов.
- Настройки и личные резервные копии остаются локальными. Для тестов можно задать `TABOTEKA_DATA_DIR` и `TABOTEKA_CONFIG` до импорта Python-модулей; GUI-установщик использует стандартные пути рядом с приложением.

## Проверка релиза

```powershell
python -m unittest discover -s tests -v
pnpm install --frozen-lockfile
pnpm build
pnpm audit
python scripts/check_publication.py
```

В браузере проверяются поиск, смена разделов/сортировки, фильтр формата, открытие и закрытие карточки и настроек с клавиатуры, отсутствие горизонтального переполнения на узкой ширине, ошибки консоли. На Windows вручную проверяются два сценария Guitar Pro: программа уже работает; программа полностью закрыта. Изолированные тесты подменяют запуск и не могут подтвердить работу GUI/DDE.
